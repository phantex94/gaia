# Compatibility and enforcement boundaries

Declared target: **Herdr host 0.9.5 + herdr-projects plugin 1.2.27**. Plugin baseline: tag `v1.2.27` (release "HP-8: Release 1.2.27", 2026-10-28; peeled commit recorded as the value `4a351c7`). Host baseline: tag `v0.9.5`. The plugin manifest requires host >=0.9.3 on linux/macos (`herdr-plugin.toml:5,7`), so the declared host meets the version gate. On the human's Mac, the 2026-11-18 audit observed both versions in the CLI, keeper, serve, and board processes. No gaia runtime rehearsal has run on this pair. Treat the versions as user-provided facts; verify the actual binaries and server without asking the same question again. Do not conflate host and plugin versions, and do not upgrade or downgrade either incidentally.

The original `eliasstravik/herdr-projects` repository redirects to `eliasstravik/shepherdr`; `bin/run.sh:31` still downloads releases from the old name. Legacy `PROJECT.md`/`thread_agent` workflows and current upstream main are not this pinned configuration model.

Paths below refer to [the pinned source tree](https://github.com/eliasstravik/shepherdr/tree/v1.2.27). Line numbers are for that tag.

| Requirement | v1.2.27 evidence | Setup boundary |
|---|---|---|
| Effective configuration | `crates/core/src/store/settings/lookup.rs:1-5`, `docs/settings.md:29-31`: task → user repo entry → you → repo file → built in. Instructions add up, broadest first; `none` cancels broader places (`lookup.rs:115-117`). Settings are read when each step starts (`docs/settings.md:45`) | Inspect all scopes. Repository config alone cannot guarantee effective settings. A change applies from the next step, not to a step under way. |
| Repo file fields | `crates/core/src/store/settings_list.rs`: `.repo()` marks `research.only`, `chat.only`, `workspace.setup/include/teardown`, `check.command`, `check.again`, `check.timeout`, `merge.pushTimeout`, `repo.key`. Nested JSON (`docs/chat.md:57`). The file is read from the commit the worktree started from (`docs/settings.md:61-65`) | Use the installed schema, not a hardcoded list: the prose at `docs/settings.md:61` omits `check.again` and `merge.pushTimeout`. Board and coordinator settings are never read from the repo file. |
| Coordinator scopes | `docs/settings.md:34-44`: this time → this coordinator → you → built in. `set … --main-coordinator`, `--machine-coordinator`, or `--project-coordinator <repo>`; `coordinator --project <repo>` talks to that coordinator | A `coordinator.instructions` value set with `--project-coordinator` reaches only that repo's project coordinator, not the main chat. Project rules for the main coordinator belong in the repo's `AGENTS.md` and its board repo entry. |
| Roles, access, fallback | `docs/settings.md:144-155`: worker `claude`, reviewer `codex`; access `full`, `ask`, or `auto`; `worker.fallback`/`reviewer.fallback` (`:149`) | Preserve user preference. Neither a reviewer prompt nor `ask`/`auto` establishes a read-only runtime. |
| Repair and review | `review.rounds` defaults to 3 (`docs/settings.md:197`) and caps check repair (`crates/flow/src/finish/pipeline.rs:120-121`), research send-back (`crates/flow/src/finish/research.rs:26`), the review loop (`crates/flow/src/finish/pipeline_end.rs:93-95`), and fallback handover (`docs/settings.md:149`) | Set it explicitly so it is visible. `0` stops every automatic send-back, including check repair, even with `review.when never`; never set `0` once a `check.command` exists. A separate check-repair budget is patch-required; patches are deferred. |
| Review selection | `review.when` `repos`/`always`/`never`; `review.mustFix`; `review.timeout` (`docs/settings.md:195-198`) | Use proportional review: `review.when never` globally plus `always` per task for major or risky work. |
| Merge and planning | `merge.by` `you`/`itself` (`:203`); `merge.checks`, `merge.sync` (`:207,209`); `plan.approve` `none`/`you`/`reviewer` (`:190`); `attempts.by`/`attempts.pick` (`:188-189`) | Reuse authorization. Do not require approval for every deterministic repair. Automatic merge requires explicit authority. |
| Limits | `limit.time` per run, `limit.tokens` counted at the end of each turn (`docs/settings.md:201-202`); `board.agents` (`:211`) | No deadline concept: a deadline task waiting for a slot is advisory prompt text. Do not advertise an instantaneous hard cap or complete accounting for nested harness agents. |
| Direct execution | `crates/flow/src/coordinator/rules.rs:33`: the coordinator adds tasks; it works directly only when the human plainly asks | Automatic small-task routing requires a patch. Appended instructions alone do not override fixed rules reliably. |
| Dependencies | `crates/flow/src/after.rs`, `crates/flow/src/after/pass.rs:10`: `--after` edges use board completion, also across machines | Preserve cycle checks. Artifact- or evidence-sensitive edges are patch-required. Reports can legitimately satisfy report edges without merges. |
| Completion | `crates/flow/src/finish/turn_ended.rs`: hooks/transcripts, stale-round guards, event positions, stage | Preserve existing guards. Do not claim screen idle alone completes a task. |
| Check outcome | `crates/flow/src/finish/pipeline.rs:115-135`: pass or fail, plus auth-failure detection (`is_auth_failure`, `:122`); no exit-code classes | The board cannot see a business refusal. Keep refusal and exit-code semantics in the repo's own tests. |
| Check purity | `crates/flow/src/finish/pipeline.rs:140-143` commits tracked changes after a passing check ("Written by the check") | Read-only checks are a convention: anything a check writes must be git-ignored. Rejecting a changed tree is patch-required. |
| PR recovery | `crates/flow/src/finish/pipeline.rs:201-215` adopts an open PR for the head branch (`finish/already.rs`) and refuses one with the wrong base (`already::wrong_base`, `:215`); archived repos at `:228` | Preserve and test existing recovery (`tests/pull_requests_already.rs`). Test crash windows before proposing more. Do not claim full idempotency has been verified. |
| Claude helper recovery | `crates/core/src/agents/helpers.rs`, `crates/flow/src/turn.rs:38-46`, `crates/flow/src/actions/finish_stuck.rs`; tests `tests/finish_missed.rs`, `tests/rearm_stuck.rs` | Preserve this behavior; do not recreate a fix based on older assumptions. |
| Reviewer brief | `crates/flow/src/finish/review_brief.rs:43` adversarial wording; verdict pinned to the reviewed commit (`:38-39`) | Keep commit attribution; temper wording through `reviewer.instructions`; separate verification from bounded repair. |
| Harness hooks | `crates/core/src/agents/adapter.rs:26-32`: a per-launch settings file adds the turn-end hook; the user's own hooks still run | Reuse adapters, preserve hooks, avoid two completion owners. Probe installed harness versions. |
| Host Codex detection | Herdr 0.9.5 release notes remove host-installed Codex turn hooks and restore screen-based host status detection | Distinguish host integration from Projects completion. Never delete Projects or user hooks merely because host hooks changed. |
| Automations and autopilot | `docs/automations.md:24` local time zone; `:33-34` missed ticks skipped (over five minutes late). `autopilot.goal` and its limits (`docs/settings.md:161-177`) | Declare timezone and missed-run policy; do not promise catch-up. A coordinator goal is native; typed workflow edges and bounded loops are not. |
| Local builds | `bin/run.sh:3-14` chooses a fresh local build, a downloaded release of this version or newer, a new download, or an older build with a warning | Local source edits can change selection. A fork needs strict local selection. The script's own download verification is third-party integrity, outside the no-hash rule. |
| Project housekeeping | `herdr-projects --help`: `archive --repo NAME`/`restore --repo NAME` (nothing on disk deleted), `archive --done`, `sweep [--dry]` | Use `archive --repo` for folders registered by mistake. Run `sweep --dry` before `sweep`. |

Do not ship universal copy-paste settings: feature stage, upper-scope overrides, and authorization change suitable values. In this baseline, `review.*`, `merge.by`, `merge.checks`, and `plan.approve` lack `.repo()`; do not write them into a repository settings file. A user-level repository entry is a different scope. Re-probe these permissions for other versions.

The pinned installation documentation uses `herdr plugin install eliasstravik/herdr-projects` with `--ref v1.2.27` (`docs/install.md:7,23`); local checkouts use `herdr plugin link "$PWD"` and `sh bin/run.sh install` (`:29-30`). These mutate installation state. Rehearse in isolation; do not use them as probes. A checkout is not proof of which executable a running keeper uses.

Plugin patches (separate repair budget, read-only check, refusal-aware check) are deferred: live with the conventions in the right-hand column until the human starts a fork.
